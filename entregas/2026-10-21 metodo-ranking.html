How we rank AI models for each type of task

From 1 row of the LMArena data to a top 3 for each type of task, step by step.

The result: for each of 10 types of task (for example "Math, hard"), a ranking of the AI models from best to worst, plus the chance that any model beats any other on that type of task. The order of model A and model B in the data doesn't matter, step 3 shows why.
1

What 1 row of the data is

A person types a question on LMArena. LMArena picks 2 models at random, shows both answers side by side without the model names, and the person votes for the better answer. Each row is 1 vote. This is a real row from the data:

model_amodel_bwinneris_codemath…
gpt-4.1claude-opus-4model_bTRUETRUE…

So in this vote Claude Opus 4 beat GPT-4.1 on a coding question. The TRUE/FALSE labels describe the question and come with the data.

2

Which votes we use

  • Only the 1st vote of each conversation. After a vote the conversation can continue with 2 new models that see the earlier answers, so later votes aren't clean.
  • Only the 48 models with 1,000+ votes (out of 53). The other 5 have too few votes to rank.
  • Only votes with a winner. "Tie" and "both bad" (27% of votes) don't say which model is better, so they're left out of the ranking.

That leaves 106,630 votes, and 77,863 of them have a winner.

3

Model A and model B are just the left and right side of the screen

Which model shows up on the left (A) or the right (B) is random, so it means nothing. To get rid of it, we split every vote into 2 lines, 1 for each model, with a 1 if it won and a 0 if it lost:

modelwontask type
claude-opus-41Code (hard)
gpt-4.10Code (hard)

If the same 2 models had been shown in the opposite order, we would get the exact same 2 lines. From here on there is no A or B, only models that won or lost. R does this split for all votes with a few lines of code.

4

Each vote gets 1 of 10 task types

We use the labels that come with the data. We go down this list and the vote takes the 1st type that is TRUE, so every vote ends up in exactly 1 type:

ordertask typelabel in the data
1stCodeis_code
2ndMathmath
3rdCreative writingcreative_writing
4thFollowing instructionsif
5thEverything elsenone of the above

Then each one is split into easy or hard. The data has 7 TRUE/FALSE labels about the question (complex, needs expert knowledge, problem solving, etc.), and a question is hard when 6 or more are TRUE. That's the same rule LMArena uses for its "Hard Prompts" category. 5 types × easy or hard = 10 types.

The row in step 1 is code, and 6 of its 7 labels are TRUE, so it's Code (hard).

5

Win rate: how often each model wins in each task type

Inside each task type we count, for every model, the votes it was in and the votes it won. Win rate = votes won ÷ votes it was in.

Example with simple made-up numbers · Math (hard)
modelvotes it was invotes it wonwin rate
Gemini40026065%
Claude40022055%
ChatGPT40018045%

This is already a ranking, and anyone can check it by hand. Its only weakness is that it doesn't look at who each model played against. A model that happened to face weaker models would look better than it is.

6

Logistic regression: the same ranking, adjusted for who each model played

We fit 1 logistic regression for each task type. It gives every model a strength score, and the chance that one model beats another depends only on the difference between their scores.

Response (y)1 if the model on the left won, 0 if the model on the right won
Predictors (x)1 column per model: +1 if it's on the left, −1 if it's on the right, 0 if it isn't in the vote
Coefficients1 per model = its strength in that task type. 1 model is set to 0 as the reference
Same method LMArena usesIt's called Bradley-Terry, and it's the method behind LMArena's own leaderboard

The real row from step 1, and the same vote if the sides had been swapped:

voteclaude-opus-4gpt-4.1other 46 modelsy
GPT left, Claude right, Claude won−1+100
Claude left, GPT right, Claude won+1−101

Flipping the sides flips every sign and the answer together, so both lines tell the regression the same thing, that Claude beat GPT. That's why the order of A and B can't change the result.

What the regression gives back:

chance left model wins = 1 / (1 + e−(strength left − strength right))
Example with simple made-up numbers · Math (hard)
modelstrength (coefficient)
Gemini0.4
Claude0.2
ChatGPT0 (reference)

Gemini vs Claude in Math (hard): 0.4 − 0.2 = 0.2, and 1 / (1 + e−0.2) = 55% chance Gemini wins. Gemini vs ChatGPT: 0.4 − 0 = 0.4, which gives 60%.

7

What comes out

10 regressions give 10 sets of strength scores, 1 for each task type. Sorting each set from highest to lowest gives the ranking for that type, and the top 3 is the recommendation:

8

How we test that it works

  • Train on the votes from April 17 to June 30, 2025.
  • Test on the July votes, which the regression never saw. For each July vote we predict that the model with the higher strength in that task type wins, and count how often we're right.
  • Compare with 1 overall ranking for all tasks, which is how LMArena's main leaderboard works. If the ranking by task type is right more often, the task types add something. If not, that's also a finding: one model is best at almost everything.
·

Why the comparison between models is fair

The person writes the question before knowing which models will answer it, and the 2 models are picked at random. So every model gets close to the same mix of questions. We checked it: 29% of all questions involve code, and every model got between 26% and 35%. The task type in step 4 and the regression in step 6 take care of the difference that's left.

Data: LMArena human preference dataset, 135,634 votes, April 17 to July 24, 2025 (huggingface.co/datasets/lmarena-ai/arena-human-preference-140k). Numbers marked as examples are made up to show the math.
